# Divergence ledger

Every edit Know Your Synth carries to a file Sunrise owns. Without this list, the next upstream
sync would rediscover these edits as conflicts, or clobber them. The format is Sunrise's
(`CUSTOMIZATION.md`, "The divergence ledger"); the rule is `sunrise.divergences` in the Hub's
`hub://process/sunrise-fork`. **An edit to a platform-owned file gets a row here in the same PR**,
and each row names what deletes it.

- **Base:** Sunrise `v0.18.0` (`68df9103e`). `lib/sunrise-version.ts` reads `0.18.0`. The fork was
  cut from `main` at `0e685744` (`v0.13.0-29`). It took `v0.14.0` in t-16, `v0.15.0` in t-77,
  `v0.16.0` in t-136, `v0.17.0` with `v0.17.1` in t-188, and `v0.18.0` in t-216. After a sync,
  move the base to the commit merged.
- **Re-derive the list (modified and deleted files) with:**
  `git diff --diff-filter=MD --name-only 68df9103e HEAD -- . ':!lib/app' ':!components/app' ':!.context/app' ':!prisma/schema/app*.prisma' ':!prototype'`
  Every file it prints is a row below, or is under "Routine edits" or "Excluded".
- **At a sync** (`CUSTOMIZATION.md` §9): read the rows before you merge, not after. For each row,
  check its **Delete when**. For a row citing `sunrise#N`, check the issue itself with
  `gh issue view N --repo human-centric-engineering/sunrise --json state,stateReason`, because
  the changelog lists only what shipped. Retire every row the release discharges by taking
  upstream's change in place of our edit, then resolve the remaining conflicts by each row's
  merge action.
- **Upstream** starts with the issue a row is carried for, `sunrise#N`, which the Hub counts. `none`
  is for an edit no upstream change should remove, and says why.

## Routine edits, not rows

CUSTOMIZATION.md's ledger section leaves these out, because the guide already says how to merge
them:

- **`package.json` and `package-lock.json`** (§7): the name `knowyoursynth@0.1.0`, its description,
  keywords and URLs, our scripts (`predev`, `prebuild`, `build:audio-workers`,
  `build:panel-renderer`, `check:synths`, the `smoke:*` additions, `bank:reindex`), our `dev`,
  which runs Sunrise's `node scripts/dev-server.mjs next-dev` under the worklet watcher
  (`tsx scripts/build-audio-workers.ts --watch -- …`, t-248; keep that wrapper round whatever
  upstream's `dev` becomes), and our
  dependencies (`esbuild`, the `@fontsource/*` faces, `@resvg/resvg-js`). On conflict: keep ours for
  identity, take the union of scripts and dependencies, then run `npm install --package-lock-only`
  and `npm run fix:lockfile-libc` (local npm strips every `libc` field).
- **`CLAUDE.md`'s Hub block** (§1): everything between the `hce-hub:bootstrap` markers is Know Your
  Synth's, as served by `get_project_bootstrap`, and the preface that told a fork to skip it is
  deleted. On conflict: never take upstream's block. Replace it with a fresh bootstrap, and merge the
  rest of the file as upstream has it.
- **The home, about and contact pages** (§6): `app/(public)/page.tsx`, `about/page.tsx` and
  `contact/page.tsx` are `app:shim` one-line re-exports of `components/app/marketing/*-page.tsx`
  (`f-front-door` t-63). On conflict: keep ours. If upstream changed a page's behaviour rather than
  its copy, carry that into our module.
- **`app/brand-theme.css`** (§2): the consumer surface's palette, which ships empty for the fork
  (`.context/ui/surface-theming.md`).

## New files in platform directories

add/add conflict, and the modified-files list never shows one. List the fork's new files outside
the reserved namespaces with:

`git diff --diff-filter=A --name-only 68df9103e HEAD -- . ':!lib/app' ':!components/app' ':!.context/app' ':!prisma/schema/app*.prisma'`
